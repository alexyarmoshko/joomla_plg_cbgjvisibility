# Yak Shaver CB GJ Event Visibility

Joomla 5 system plugin (`plg_system_cbgjvisibility`) that hides selected CB GroupJive event details from guest users by post-processing rendered HTML in `onAfterRender`.

## What it does

- Hides event host, group link, and guest count from anonymous visitors (enabled by default).
- Optionally hides event description blocks.
- Keeps logged-in users untouched.
- Provides a "Test Sanitization" button in plugin settings that fetches the front page as a guest and verifies hidden CSS classes are absent.

## Repository layout

- `cbgjvisibility.xml`: Plugin manifest and config parameters.
- `services/provider.php`: Joomla DI registration for the plugin class.
- `src/Extension/Cbgjvisibility.php`: Main plugin logic.
- `src/Field/SanitizationTestField.php`: Admin custom field with Test Sanitization button.
- `media/js/sanitization-test.js`: Admin Testing tab behavior (AJAX sanitization test UI).
- `language/en-GB/`: Plugin language strings.
- `plg_system_cbgjvisibility.update.xml`: Update descriptor template; the published descriptor is generated by `make dist_release`.
- `Makefile`: Reproducible packaging and release gates (see [Build](#build)).
- `tools/jzip.php`: Deterministic ZIP writer used by the build; not shipped in the package.
- `docs/RELEASE.md`: Release notes.

## Updates

Joomla offers new releases under **System → Update → Extensions**. Sites on 1.0.2 or earlier need to install 1.0.3 manually once.

## Build

Requires a POSIX shell (Linux, macOS, Git Bash or WSL), `make`, `git`, and PHP with the `zlib` and `SimpleXML` extensions.

| Target | Purpose |
|---|---|
| `make info` | Show the version, shipped files and output paths. |
| `make lint` | Lint the PHP and XML files. |
| `make dist_dev` | Build a test package from the working tree into `installation/dev/`. |
| `make release` | Check the release prerequisites and tag the manifest version. |
| `make dist_release` | Build the release package and update descriptor from the tag into `installation/release/`. |
| `make clean` | Remove build output. |

Release packages from 1.0.3 on are reproducible: rebuilding a tag with a compatible zlib gives a byte-identical ZIP.

### Releasing

1. Bump `<version>` in `cbgjvisibility.xml` and `plg_system_cbgjvisibility.update.xml`, add a `## <version> (<date>)` heading to `docs/RELEASE.md`, and commit.
2. Run `make release`, then `make dist_release`.
3. Push the tag and upload the ZIP from `installation/release/` to the GitHub release.
4. Publish `installation/release/plg_system_cbgjvisibility.update.xml` at the update server URL in the manifest.

The tracked `plg_system_cbgjvisibility.update.xml` is a template; keep its `<sha256>` as 64 zeros.

## Configuration

Plugin settings are split into:

- `General`: Toggle `hide_host`, `hide_group`, `hide_guests`, `hide_description`.
- `Selectors`: Configure wrapper element/class and marker string used by the stripping logic.
- `Testing`: Run a live sanitization test against the front page.

## Testing sanitization

1. Open plugin settings in Joomla administrator.
2. Go to the Testing tab and click "Test sanitization".
3. The plugin fetches the site's front page as a guest and checks that hidden CSS classes are absent from the HTML.

## Notes

- The HTML stripping assumes target `class="..."` attributes use double quotes in CB templates.
- Description block stripping uses nesting-aware parsing to handle nested `<div>` content.
